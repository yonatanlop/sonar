Introducción y Arquitectura del Sistema

1.1 ¿Qué es SONAR?

SONAR es una plataforma de monitoreo de redes sociales diseñada para recolectar, analizar y alertar sobre menciones de entidades (personas, organizaciones, productos o marcas) en plataformas digitales como Reddit, YouTube, Twitter/X y fuentes RSS de noticias.

El sistema recolecta publicaciones de forma automática, aplica análisis de sentimiento e identificación de discurso de odio, y notifica al equipo cuando se detectan situaciones que requieren atención según reglas configuradas.

ℹ️
Este manual cubre la versión 1 de SONAR, que incluye el motor de scraping, el pipeline NLP básico (sentimiento, idioma, discurso de odio, urgencia), el sistema de alertas y la generación de reportes PDF.

1.2 Componentes principales

ComponenteTecnologíaFunción
FrontendReact 18 + Vite + TailwindInterfaz web de usuario
Backend (API)FastAPI (Python)API REST — lógica de negocio, autenticación
WorkerCeleryTareas en segundo plano: scraping, NLP, alertas
Scheduler (Beat)Celery BeatDisparador de tareas programadas (crons)
Base de datosPostgreSQL 15Almacenamiento persistente de todas las entidades
Caché / ColaRedis 7Cola de tareas y caché de sesiones

1.3 Flujo general de datos

⚙️
1. Configuración
Se definen entidades y palabras clave que el sistema debe buscar
🔍
2. Recolección
El Worker scraping busca menciones en Reddit, YouTube, RSS y Twitter cada 15-30 min
🧠
3. Análisis NLP
Cada mención nueva pasa por el pipeline: idioma → sentimiento → odio → urgencia
📊
4. Almacenamiento
Las menciones procesadas se guardan en PostgreSQL con todos sus scores
🔔
5. Evaluación de reglas
Cada 5 min el motor de alertas evalúa si alguna regla supera su umbral
📱
6. Notificación
Si se dispara una alerta, se envía por Telegram, email o WhatsApp
💡
El panel de Dashboard muestra en tiempo real los totales de menciones, distribución de sentimiento, plataformas activas y alertas del día. Es el punto de partida para el monitoreo diario.

2.2 Obtención del código fuente

Clona el repositorio y accede al directorio del proyecto:

# Clonar el repositorio
git clone https://github.com/yonatanlop/sonar.git
cd sonar

# (Opcional) Para la versión con IA (v2), cambiar a la rama version2
git checkout version2

2.3 Configuración del archivo .env

El archivo .env contiene todas las credenciales y parámetros de configuración. Copia la plantilla y édita los valores necesarios: 

cp .env.example .env

Las variables más importantes son:

Base de datos y seguridad (obligatorias)

# ── Base de Datos ──────────────────────────────────────────
POSTGRES_DB=sonar_db
POSTGRES_USER=sonar_user
POSTGRES_PASSWORD=cambia_esta_clave_segura
DATABASE_URL=postgresql://sonar_user:cambia_esta_clave_segura@db:5432/sonar_db

# ── Seguridad JWT ──────────────────────────────────────────
# Genera una clave aleatoria de 64 caracteres:
# python -c "import secrets; print(secrets.token_hex(32))"
SECRET_KEY=pon_aqui_64_caracteres_aleatorios
REDIS_URL=redis://redis:6379/0

Plataformas de scraping (opcionales — solo configura las que uses)

# ── Reddit ────────────────────────────────────────────────
REDDIT_CLIENT_ID=tu_client_id_de_reddit
REDDIT_CLIENT_SECRET=tu_client_secret_de_reddit
REDDIT_USER_AGENT=SONAR/1.0 (monitor por tu_usuario)

# ── YouTube ──────────────────────────────────────────────
YOUTUBE_API_KEY=tu_api_key_de_youtube_data_v3

# ── HuggingFace (NLP Sentimiento/Odio) ───────────────────
NLP_MODE=api
HUGGINGFACE_TOKEN=hf_tu_token_de_huggingface

Notificaciones (opcionales)

# ── Telegram ─────────────────────────────────────────────
TELEGRAM_BOT_TOKEN=123456:tu_token_del_bot_telegram

# ── Email (Gmail) ────────────────────────────────────────
GMAIL_USER=tu_cuenta@gmail.com
GMAIL_APP_PASSWORD=xxxx xxxx xxxx xxxx
⚠️
Importante: si cambias POSTGRES_PASSWORD, asegúrate de actualizarla también dentro de DATABASE_URL. Ambas deben coincidir exactamente.

2.4 Levantando los servicios con Docker

Con el archivo .env configurado, ejecuta:

# Primera vez: construir imágenes y levantar todos los servicios
docker compose up --build -d

# Ver el estado de los contenedores (todos deben aparecer como "running")
docker compose ps

# Seguir los logs en tiempo real (útil para diagnosticar problemas)
docker compose logs -f backend

Los 6 servicios que deben estar corriendo:

ServicioPuertoEstado esperado
db5432healthy
redis6379healthy
backend8000running
worker—running
beat—running
frontend3000running
ℹ️
El backend ejecuta automáticamente las migraciones de base de datos (alembic upgrade head) al iniciar. Esto crea todas las tablas necesarias en la primera ejecución.

2.5 Creación del usuario administrador

Antes del primer acceso necesitas crear un usuario admin. Ejecuta el script incluido: 

# Crear el primer usuario administrador
docker compose exec backend python scripts/create_admin.py

# El script pedirá interactivamente:
#   Nombre de usuario: admin
#   Email: admin@ejemplo.com
#   Contraseña: (mínimo 8 caracteres)
#   Nombre completo: Administrador SONAR
✅
Una vez creado el usuario administrador, el sistema está listo para acceder en http://localhost:3000

Entidades: Qué Monitorear

5.1 ¿Qué es una entidad?

Una entidad es el sujeto que quieres monitorear: puede ser una persona (político, ejecutivo, influencer), una organización (empresa, partido, institución) o un producto/marca. Todo el análisis del sistema gira en torno a las entidades.

Cada entidad tiene:

  • Nombre principal — Ej: "Petro", "Bancolombia", "iPhone"
  • Aliases — Variaciones del nombre: "Gustavo Petro", "@petrogustavo"
  • Palabras clave (keywords) — Términos de búsqueda que capturan menciones
  • País — Para filtrar y contextualizar menciones geográficamente
  • Tipo de entidad — Politician, Company, Celebrity, etc.
ℹ️
Flujo de configuración en dos pasos:
El formulario de creación captura los datos básicos (nombre, tipo, país, descripción y foto). Los aliases y las keywords se agregan en la página de detalle de la entidad una vez que esta ha sido creada — ver secciones 5.3 y 5.4.

5.2 Crear una entidad

Ruta: Entidades › Nueva entidad

  1. En el menú lateral, haz clic en Entidades
  2. Haz clic en el botón + Nueva entidad
  3. Completa el formulario:
    • Nombre — Nombre principal de la entidad (ej: "Bancolombia")
    • Tipo — Selecciona el tipo: Company, Politician, Celebrity, etc.
    • País — País de origen o relevancia geográfica
    • Descripción — Texto descriptivo opcional para contexto del equipo
    • Foto URL — URL de imagen de perfil (opcional)
  4. Haz clic en Guardar
  5. El formulario se cierra y la entidad aparece en la lista. Haz clic en Ver detalle para continuar con la configuración (aliases y keywords)
ℹ️
Las entidades sin keywords configuradas no recibirán menciones ya que el scraper no sabe qué buscar. El siguiente paso es siempre agregar al menos una palabra clave.

5.3 Agregar aliases

Los aliases son nombres alternativos de la entidad. El sistema los usa en el motor de alertas y en la búsqueda de contexto, pero no en el scraping directo.

Ruta: Entidades › [clic en entidad] › Aliases

  1. Desde el detalle de la entidad, localiza la sección Aliases
  2. Escribe el nombre alternativo en el campo de texto (ej: "@Bancolombia", "Banco Colombia")
  3. Haz clic en Agregar
  4. Repite para cada variación relevante del nombre
💡
Ejemplos de buenos aliases:
  • Para "Gustavo Petro" → Petro, @petrogustavo, Presidente Petro
  • Para "Ecopetrol" → @Ecopetrol, ECO, Ecopetrol S.A.
  • Para "iPhone 16" → iphone16, iPhone16Pro, Apple iPhone

5.4 Configurar palabras clave (keywords)

Las keywords son los términos exactos que el scraper busca en las plataformas. Cada keyword se asocia a un idioma y tiene un peso que indica su importancia.

Ruta: Entidades › [clic en entidad] › Keywords

Niveles de peso (importance)

PesoIndicadorUso recomendado
1 — Normal Gris Términos generales de seguimiento. Ej: "bancolombia productos"
2 — Importante Amarillo Términos relevantes con más atención. Ej: "bancolombia fraude"
3 — Crítico Rojo Términos de riesgo alto. El motor de alertas keyword_critical solo dispara con peso 3
  1. Desde el detalle de la entidad, localiza la sección Keywords
  2. Escribe la palabra o frase clave en el campo (ej: "bancolombia estafa")
  3. Selecciona el idioma de la keyword (ES / EN)
  4. Elige el peso (1, 2 o 3)
  5. Haz clic en Agregar keyword
⚠️
Buenas prácticas para keywords:
  • Usa términos específicos para evitar falsos positivos
  • Incluye variantes con y sin tildes: "petróleo", "petroleo"
  • Incluye el nombre de la entidad junto al tema: "Ecopetrol derrame" en vez de solo "derrame"
  • Agrega keywords en inglés si la entidad tiene presencia internacional

5.5 Detalle de entidad y métricas

Al hacer clic en cualquier entidad en la lista, accedes a su página de detalle con:

  • Gráfico de volumen — Menciones diarias de los últimos 30 días
  • Distribución de sentimiento — Donut chart con % de cada categoría
  • Top menciones — Las publicaciones con mayor reach (interacciones)
  • Plataformas activas — Distribución por red social
  • Keywords activas — Lista editable de palabras clave
  • Accesos rápidos — Botones para ver alertas y generar reporte de esa entidad

Configuración de Plataformas de Scraping

SONAR recolecta menciones de cuatro fuentes. Cada una requiere credenciales propias configuradas en el archivo .env. Las plataformas no configuradas son saltadas silenciosamente sin causar errores.

6.1 Reddit

Frecuencia: cada 15 minutos  |  Requiere: cuenta de Reddit + app registrada

Cómo obtener credenciales de Reddit

  1. Inicia sesión en reddit.com con tu cuenta
  2. Ve a https://www.reddit.com/prefs/apps
  3. Haz clic en Create App (o "Create another app")
  4. Rellena el formulario:
    • Name: SONAR Monitor
    • App type: script
    • redirect uri: http://localhost:8080
  5. Haz clic en Create app
  6. Copia el client_id (texto bajo el nombre de la app) y el client_secret
REDDIT_CLIENT_ID=abc123xyz
REDDIT_CLIENT_SECRET=SecretKeyABC123
REDDIT_USER_AGENT=SONAR/1.0 (monitor by tu_usuario_reddit)
💡
El REDDIT_USER_AGENT puede ser cualquier texto descriptivo. Reddit lo usa para identificar tu aplicación. Usa el formato AppName/version (descripcion).

6.2 YouTube

Frecuencia: cada 30 minutos  |  Requiere: cuenta de Google + proyecto en Cloud Console

Cómo obtener YouTube Data API Key

  1. Ve a console.cloud.google.com y crea un proyecto nuevo (ej: "SONAR")
  2. En la barra de búsqueda, busca YouTube Data API v3 y habilítala
  3. Ve a Credenciales → Crear credenciales → Clave de API
  4. Copia la clave generada
  5. Opcionalmente, restringe la clave a "YouTube Data API v3" para mayor seguridad
YOUTUBE_API_KEY=AIzaSyAbc123DefGhi456
⚠️
La API de YouTube tiene una cuota gratuita de 10,000 unidades/día. Cada búsqueda consume ~100 unidades. Con múltiples entidades y keywords, puedes alcanzar el límite rápidamente. Monitorea el uso en Google Cloud Console.

6.3 RSS / Noticias web

Frecuencia: cada 20 minutos  |  Requiere: nada (funciona sin credenciales)

El scraper RSS lee automáticamente fuentes de noticias preconfiguradas y filtra artículos que contengan las keywords de cada entidad. No requiere configuración adicional.

ℹ️
Las fuentes RSS incluyen portales de noticias regionales e internacionales en español e inglés. Si necesitas agregar una fuente específica, contacta al administrador del sistema o edita el archivo backend/app/workers/scrapers/rss.py.

6.4 Twitter / X

Frecuencia: cada 20 minutos  |  Requiere: una cuenta de Twitter (sin API key oficial)

SONAR usa twscrape, una herramienta que permite buscar en Twitter sin API key oficial, usando credenciales de usuario. Necesitas agregar al menos una cuenta de Twitter.

  1. Asegúrate de tener una cuenta de Twitter/X activa (puede ser una cuenta de uso exclusivo para el monitoreo)
  2. Ejecuta el script de configuración: 
    docker compose exec backend python scripts/add_twitter_account.py
  3. Ingresa el usuario, contraseña y email de la cuenta cuando se solicite
  4. El script guarda las credenciales cifradas en /app/storage/twscrape.db
⚠️
Usa una cuenta de Twitter dedicada al monitoreo, no una cuenta personal. Twitter puede solicitar verificación por email o teléfono si detecta actividad inusual.

6.5 Verificar que el scraping está funcionando

Después de configurar las credenciales, reinicia los servicios para aplicar los cambios:

# Reiniciar solo el worker y el beat (donde corre el scraping)
docker compose restart worker beat

# Verificar logs del worker para ver si el scraping corre sin errores
docker compose logs worker --tail=50

En los logs busca mensajes como:

# Indicadores de éxito
[RedditScraper] Entidad "Bancolombia": 12 menciones nuevas
[YouTubeScraper] Entidad "Ecopetrol": 3 videos encontrados
[RSSScraper] 7 artículos procesados
💡
También puedes monitorear el estado de las tareas en tiempo real usando Flower (interfaz web de Celery) en http://localhost:5555. Muestra cada tarea ejecutada, su duración y si tuvo errores.

Sistema de Alertas

El sistema de alertas evalúa reglas configuradas cada 5 minutos de forma automática. Cuando una regla supera su umbral, se genera una alerta visible en el panel y (si está configurado) se envía una notificación por Telegram, email o WhatsApp.

8.1 Tipos de reglas de alerta

Tipo de reglaQué detectaUmbral típico
volume_spike Pico en el volumen de menciones comparado con el promedio histórico de 7 días 2× el promedio
negative_threshold Porcentaje de menciones negativas o muy negativas supera un umbral 40% o más
bot_activity Número de cuentas clasificadas como bots mencionando la entidad en el período 5 o más bots
keyword_critical Menciones que contienen palabras clave de peso 3 (crítico) 1 o más menciones
hate_speech Número de menciones con discurso de odio detectado 3 o más menciones
campaign_detected Mensajes muy similares (≥75%) provenientes de 3 o más cuentas distintas (posible campaña coordinada) 3 cuentas distintas
ℹ️
Para que keyword_critical funcione correctamente, debes tener keywords con peso 3 configuradas en la entidad. Si no hay keywords de peso 3, esta regla nunca disparará.

8.2 Crear una regla de alerta

Ruta: Reglas de Alerta › Nueva regla

  1. En el menú lateral, haz clic en Reglas de Alerta
  2. Haz clic en el botón + Nueva regla
  3. Completa el formulario:
    • Nombre — Descripción corta de la regla (ej: "Pico negativo Ecopetrol")
    • Entidad — Selecciona la entidad específica o deja en blanco para una regla global (aplica a todas)
    • Tipo de regla — Elige uno de los 6 tipos de la tabla anterior
    • Umbral — Número que dispara la alerta (ver tabla de ejemplos abajo)
    • Ventana de tiempo — Minutos que el sistema evalúa hacia atrás (ej: 60 = última hora)
    • Severidad — Cómo se clasifica la alerta si se dispara
  4. Haz clic en Crear regla

8.4 Identificar una alerta activa

Cuando el motor de alertas dispara una regla, aparece un indicador en la barra de navegación superior. Para ver las alertas activas:

Ruta: Menú lateral › Alertas

En la vista de Alertas, cada tarjeta contiene:

CampoDescripción
Ícono de severidadColor y ícono que indica el nivel de criticidad
Nombre de la reglaLa regla que se disparó (ej: "Pico negativo Ecopetrol")
Mensaje descriptivoExplica qué ocurrió: qué métrica superó qué umbral
EntidadA qué entidad afecta la alerta
Hora de disparoCuándo fue detectada la situación
EstadoPendiente (sin revisar) o Reconocida
🚨
Protocolo ante una alerta crítica:
  1. Lee el mensaje de la alerta y confirma la entidad afectada
  2. Ve a Menciones y filtra por esa entidad + sentimiento negativo
  3. Revisa las menciones recientes para entender el contenido de la situación
  4. Evalúa si requiere respuesta pública, escalamiento interno o solo monitoreo
  5. Reconoce la alerta para indicar al equipo que fue vista y gestionada

8.5 Reconocer (acknowledge) una alerta

Reconocer una alerta indica que fue revisada y está siendo atendida. Esto la mueve a estado Reconocida y registra qué usuario la atendió.

  1. En la vista de Alertas, localiza la alerta que deseas reconocer
  2. Haz clic en el botón Reconocer en la tarjeta de la alerta
  3. La alerta cambia a estado Reconocida y registra tu nombre y la hora
ℹ️
Reconocer una alerta no desactiva la regla. Si la condición persiste, la regla puede dispararse de nuevo después del período de cooldown (30 minutos).

Administración y Mantenimiento

10.1 Monitoreo de tareas con Flower

Flower es la interfaz web de Celery que permite ver en tiempo real qué tareas se están ejecutando, cuánto tardan y si han fallado.

Accede en: http://localhost:5555

Sección de FlowerQué muestra
DashboardTareas activas, completadas y fallidas en tiempo real
TasksHistorial de todas las tareas ejecutadas con duración y resultado
WorkerEstado del worker de Celery (online/offline, recursos)
BrokerEstado de la cola Redis y mensajes pendientes

10.2 Limpieza automática de datos

El sistema ejecuta una tarea de limpieza diariamente a las 3:00 AM que elimina menciones con más de 365 días de antigüedad. Esto mantiene el tamaño de la base de datos bajo control.

⚠️
Si necesitas conservar menciones históricas más allá de un año, exporta o genera reportes PDF antes de que sean eliminados. La eliminación es irreversible.

10.3 Solución de problemas comunes

No llegan menciones nuevas

  1. Verifica que el worker y el beat están corriendo: docker compose ps
  2. Revisa los logs del worker: docker compose logs worker --tail=100
  3. Confirma que la entidad tiene al menos una keyword activa
  4. Verifica que las credenciales de las plataformas son correctas en .env

El análisis NLP no procesa menciones

  1. Verifica que HUGGINGFACE_TOKEN está configurado y es válido en .env
  2. Revisa los logs: docker compose logs worker --tail=50 | grep NLP
  3. HuggingFace tiene un límite de 1,000 peticiones/día en el tier gratuito — puede estar agotado

Las alertas no llegan por Telegram

  1. Verifica que TELEGRAM_BOT_TOKEN en .env es correcto
  2. Confirma que el Chat ID del usuario en el perfil es correcto (numérico)
  3. Asegúrate de haber enviado un mensaje previo al bot para desbloquearlo
  4. Revisa los logs: docker compose logs worker | grep Telegram

El contenedor de la base de datos no inicia

# Ver logs detallados del contenedor db
docker compose logs db

# Solución más común: reiniciar solo el contenedor db
docker compose restart db

# Si el problema persiste, verificar que el puerto 5432 no esté ocupado
docker compose down && docker compose up -d
